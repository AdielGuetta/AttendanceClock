1 · How the parts fit together

One request path, two dependencies: the database (inside Docker) and the time APIs (on the internet).

Read it like a warehouse: the browser is the worker at the gate, the API is the guard, the time APIs are the official clock the guard phones, and SQL Server is the storeroom whose shelves physically allow only one open shift per worker.

2 · What happens when someone presses Clock In

Every exit on the right is a safe refusal. Nothing is ever saved with an untrusted time.

3 · Where the user's waiting time goes

Approximate time per punch. The external time API dominates, which is the price of a trustworthy time.

User impact: a punch normally feels instant (~0.1–0.3 s). The UI will show "Recording…" during the call. In the rare double outage, the user waits about 5 s and sees "Nothing was recorded, please try again". Never a wrong time.

4 · Ten clicks at the same instant

Measured in test #8 (plan 07): the code check alone was not enough. The database made it exactly one.

User impact: double-clicking, a second tab or a second device never creates a "ghost" double shift. The extra click just gets "You're already on shift", and the screen refreshes.

6 · The core trade-off

7 · Component by component

ASP.NET Core · .NET 10 required

Backend API
+Mature and fast, with built-in DI, JWT auth, rate limiter, health checks and ProblemDetails
+LTS: supported for 3 years; runs on any OS
−More ceremony than micro-frameworks; local builds blocked by Smart App Control (solved by Docker)
→Precise error codes become friendly messages ("You're already on shift", not "Error 409")

SQL Server 2022 required

Database
+Enforces rules itself: unique filtered index, check constraint, rowversion
+datetimeoffset keeps instant + Zurich offset; strong transactions
−~2 GB image and RAM; no ARM image (emulated on Apple chips)
→No ghost double shifts, no impossible shifts; data survives restarts

EF Core 10

Database access
+Compiler-checked queries; migrations version the schema
+All table rules declared in one place
−Hides the SQL; startup auto-migration is for development only
→Indirect: fewer data bugs; a clone "just works"

Time APIs required

timeapi.io (primary) · time.now (backup)
+Punch times can't be manipulated locally
+Chosen by measurement; keyless (no sign-up for reviewers)
−Internet dependency, no SLA; backup ~70% success; one call per punch (rush risk, EC-17)
→A punch takes a moment longer; the confirmed time is the official one

Trusted clock

Fail-closed time logic
+One path for "now"; every answer validated (zone, offset, DST rules)
+Fully testable with fakes (outages, DST nights, lying providers)
−Both providers down → punches refused; worst case ~5 s wait
→Usually invisible; rarely "nothing recorded, try again", never a wrong time

JWT login

Identity and role, 60-minute tokens
+Stateless; role in the token; tampering detected
−Can't revoke early; no refresh tokens yet
−Token stored in the browser: the UI must guard against XSS
→Log in once, work an hour, then log in again

Password hashing + rate limit

PBKDF2 + salt · 5 attempts / min / IP
+A leaked database doesn't reveal passwords
+Same message and timing for "unknown user" and "wrong password"
−Limit is in memory and per IP (resets on restart; an office shares one IP)
→5 typos → "please wait a minute"; deliberately vague errors

React + Vite + TypeScript required

UI (planned)
+App-like updates; TypeScript catches mistakes early
−Needs JavaScript; more moving parts; Vite's binary may need Docker here
→One big context-aware button; "Recording…" then the official time
→Times always in Zurich time with a CET/CEST label

Docker Compose

Local environment
+One command on Windows, macOS or Linux; no local SQL Server/.NET needed
+Got around Smart App Control without touching security settings
−~3.5 GB first download; slower reload (polling); emulation on Apple chips
→Nothing for end users; clone-to-running in minutes for reviewers

Automated tests

xUnit · fake HTTP · real app + test DB
+Simulates outages, DST nights, races and attacks in seconds
+Separate test database, reset every run: dev data never touched
−Needs the DB container; costs time on a tight deadline
→Core guarantees re-checked on every change (31/31 passing)
